## 已查证的关键事实（2026-11-12，后续实现直接引用，别重查）

- `https://lyric.photix.cc/` 是网易云歌词下载网页工具（Nuxt），支持单曲链接/数字 ID → LRC/SRT 原文/翻译/双语；FAQ 明确「不可以商用，仅供个人学习交流」，并提示现场版可能需整体偏移。
- 实测内部 server route `GET /api/lyric?id=<id>`：成功返回 `lrc.lyric` / `tlyric.lyric` / `klyric.lyric` / `code`；`klyric` 示例为空；空歌词为 `[00:00.00]暂无歌词` + `uncollected=true`；非法 ID 是 **HTTP 200 + `{"code":400,"msg":"wrong params"}`**；空 id 为 HTTP 400；Content-Type 在 `text/html` 与 `application/json` 间不一致。**非公开 API、无 SLA**，必须走适配层 + 本地导入兜底。
- UVR v5.6 官方 README：CLI `python UVR.py -i/-o/-m/-v/-i_stem/-g`，`-g -1` = CPU；NVIDIA 最低 GTX 1060 6GB / 建议 ≥8GB；macOS M1 起 MPS 已扩展到 Demucs v4 与全部 MDX-Net；AMD/Intel 有 DirectML 版；依赖 FFmpeg 处理非 WAV；代码 MIT，第三方用模型须署名 UVR 及开发者；首次启动可能 5–10 分钟。
- KTV 行业约定：双音轨「原唱 → 伴奏」+ `title`/`language` 元数据；老式机顶盒偏 MPG/MPEG-2，新式支持 MP4/MKV；部分老曲库为左右声道分离（非双音轨）。

## 关键技术决策（写入文档，改动前先更新文档）

- 「音轨 0/1」定义为音频流相对序号 `a:0`/`a:1`，非容器全局 stream index；顺序由 FFmpeg `-map` 显式顺序保证。
- 不烧录字幕时强制 `-c:v copy`（视频码流零损失）；烧录必然重编码，默认关闭 + 二次确认 + 保留无字幕中间产物。
- 原唱轨也由统一 PCM 重新编码，保证两轨参数一致、切换无爆音（可用「原唱直通」开关回退）。
- 歌词失败/为空/关闭烧录三种分支必须产出**等价**的合法无字幕双音轨文件。
- 硬件加速：CUDA / MPS / DirectML 探测 + 1s 自检 → 失败自动降级 CPU 一次，禁止静默降级，UI 明示原因。
- UI/UX 引擎首轮误判 Job/Career（BM25 命中 "job queue"），已人工校正为 Developer Tool（dark，9.071）视觉基调 + Dashboard/Admin 信息架构；桌面端排除引擎的移动端条目。

## 补环境缺口：libass 与 UVR 运行时（同日 14:00–15:15）

- **libass**：宿主机 brew 的 FFmpeg 8.1 构建已不含 libass（`brew deps ffmpeg` 无 libass/freetype/harfbuzz）。取 osxexperts 的 **arm64 静态 FFmpeg 7.1**（`ffmpeg71arm.zip` + `ffprobe71arm.zip`）放 `resources/bin`，configuration 含 `--enable-libass --enable-fontconfig --enable-libharfbuzz --enable-libx265 --enable-videotoolbox`；实测 `ass`/`subtitles` 滤镜可用，中文 ASS 烧录抽帧可见文字。evermeet.cx 的构建是 **x86_64**（Rosetta），不用于随包。
- **UVR v5.6 无 CLI**：官方 README 唯一入口是 `python UVR.py`（Tkinter GUI），设计文档里的 `-i/-o/-m` 契约不成立。改用 **audio-separator 0.48.0**（Nomad Karaoke，MIT，用的就是 UVR 训练的 MDX-Net 模型），Python 3.10.15 venv 装在 userData（1.1 GB），`resources/uvr/launch_separator.py` 为启动垫片。
- **CoreML 跑不了 MDX**：audio-separator 在 Apple Silicon 硬编码优先 CoreMLExecutionProvider，MDX-Net ONNX 含其不支持的算子，报 `error code: -1`；库无关闭开关，垫片把 `Separator.setup_torch_device` 替换为固定 `CPUExecutionProvider`（MDX 走 ONNX，无功能损失）。6s 音频约 30s 完成。
- **FFmpeg 7.1 的 MP4 muxer 只写 `handler_name`**，忽略 `-metadata:s:a:N title=`（8.1 写 `udta/name` → `tags.name`）。encodeMux 现同时写 title + handler_name；`titleOf()` 兼容 title / name / handler_name。否则 V-02 硬断言会误判缺失。
- **spawn 的 cwd 不存在 → code -1**：`separate()` 补 `mkdir -p workDir`，`runProcess` 的 error 事件把真实原因写进 stderr（此前只有 -1，难定位）。
