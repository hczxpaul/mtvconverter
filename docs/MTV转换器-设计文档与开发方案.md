# MTV Converter — 设计文档与开发方案

> 版本 **v1.3** ｜ 2026-11-12
> 定位：把仅含原唱音轨的音乐 MV / 现场 live 视频，转换为**原分辨率 H.265 压缩视频** + 双音轨（音轨 0 原唱、音轨 1 伴奏）的 KTV 风格 MTV 文件；可选从歌词服务取词并烧录字幕；提供应用内预览播放器与音轨切换预览。
> 界面原则：**主页面极简**——只保留「导入 → 转换 → 预览 / 结果」+ **一个可见但默认折叠的首页歌词区**；技术细节与提示收敛到「更多设置」与「详情 / 日志」，见 §7.3 / §7.8 / §7.9。
> 本文只描述设计、接口契约与开发方案，**不含代码实现**。文中命令行仅为「外部工具调用契约示意」，用于界定集成边界。

## 0. 阅读指引与术语约定

| 术语 | 本文中的明确定义 |
| --- | --- |
| 源文件 | 用户输入的 MV / live 视频，通常只含一条原唱音轨 |
| 原唱轨 | 与源文件音频内容一致的音轨，输出中固定为音频流 `a:0` |
| 伴奏轨 | 输出中固定为 `a:1`；来源二选一：UVR5.6 分离产物，或用户导入的官方伴奏 |
| 音轨 0 / 音轨 1 | **指音频流的相对序号 `a:0` / `a:1`**，不是容器全局 stream index（含视频流时全局 index 通常为 1 与 2） |
| MTV 文件 | **满足本文输出契约的标准视频文件**（原分辨率 H.265 + 双音轨 + 可选烧录字幕），点歌系统按内容自动识别；不是任何厂商私有容器 |
| 原分辨率 | 输出宽高像素与源一致，不缩放、不裁剪；SAR / DAR、旋转显示、帧率、色彩空间与时长保持不变 |
| 压缩档 | H.265 编码的质量 / 体积档位（CRF / 目标码率），决定输出体积与画质，见 §5.3 |
| 烧录字幕 | 歌词渲染进画面（hardsub）；并入同一次 H.265 编码，不额外增加一次编码 |
| 预览代理 | 为兼容性把媒体实时转为浏览器可播的 H.264/AAC HLS（多音轨）的本地服务，见 §7.7 |
| Sidecar | 随应用分发或按需下载的外部依赖：FFmpeg / FFprobe、UVR Python 运行时、模型权重、字体 |
| Job | 一次转换任务，有唯一 jobId、中间产物目录、状态机、断点续跑标记与校验报告 |
| 提示分级 | 把每个内部事件映射为 L0 主页面 / L1 状态行 / L2 详情抽屉 / L3 必要打断的策略，见 §7.8 |

**优先级标记**：P0 = 首版必须具备；P1 = 首个正式版应具备；P2 = 增强。

## 1. 产品目标与范围

### 1.1 目标

1. **转码与压缩（P0）**：输出视频一律转为 **H.265 / HEVC**，保持**原分辨率**、帧率、时长与音画同步，并**压缩文件体积**。
2. **主目标（P0）**：输入仅含原唱音轨的 MV / live 视频，输出含两条音轨的 MTV 文件；`a:0` 原唱、`a:1` 伴奏，播放器中切换音轨即可切换原唱 / 伴奏。
3. **伴奏生成（P0）**：调用 UVR5.6 生成伴奏；**或由用户导入官方伴奏**（P1）直接替代分离阶段。
4. **歌词能力（P1，可选）**：用户提供歌曲链接时通过 `https://lyric.photix.cc/` 获取歌词；可烧录进画面。失败 / 为空 / 关闭烧录均不得阻断主流程。
5. **应用内预览（P1）**：预览播放器可预览输入视频或输出视频，并可选择 `a:0` / `a:1` 音轨预览。
6. **跨平台（P0）**：Electron 打包 Windows / macOS；Windows NVIDIA、macOS Apple Silicon 硬件加速，并明确无加速时的回退策略。
7. **极简主页面（P0）**：主页面只保留「导入 → 转换 → 预览 / 结果」；零持久横幅、零技术术语、零多卡堆叠；复杂度收敛到「更多设置」与「详情 / 日志」，见 §7.8。
8. **歌词上首页（P0）**：首页常驻一个「歌词（可选）▸」**默认折叠**区块，展开即完整歌词配置；收起时只占一行、零技术术语，见 §7.9。

### 1.2 范围边界

| 范围内 | 范围外（本期不做） |
| --- | --- |
| 本地文件转换、单任务 / 批量队列 | 视频剪辑、转场、调色、缩放 / 裁剪 |
| H.265 转码压缩、多音轨封装与校验 | 点歌系统 / 机顶盒私有格式适配（自动识别，无需适配） |
| UVR 分离生成伴奏 / 导入官方伴奏 | 从零合成伴奏、修音、升降调、变速 |
| 歌词获取 / 本地 LRC/SRT 导入 / 烧录 | 歌词自动翻译、逐字时间戳自动生成 |
| 应用内预览与音轨切换 | 在线视频下载、DRM 解除、加密片源 |
| Windows / macOS 桌面端 | Linux、移动端、Web 端、云端转码服务 |

### 1.3 典型场景（验收基线用例）

> 输入：`MV.mp4`，H.264 1080p / 30fps / 210.000s / 480 MB，仅一条 AAC 立体声原唱音轨。
> 输出：`MV.mp4`（MP4 容器，HEVC/hvc1），1920×1080 / 30fps / 210.000s，体积显著小于源（目标 ≤ 60%，实测后定稿）；`a:0` = 原唱（title=`原唱`、language=`zho`、default）、`a:1` = 伴奏（title=`伴奏`、language=`zho`）；按配置可在画面叠加歌词字幕。
> 应用内预览可切换 a:0 / a:1，切换不中断播放、进度不跳；点歌系统按内容自动识别。

## 2. 需求规格

### 2.1 功能需求

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FR-01 | 导入本地视频（拖拽 / 选择 / 批量） | P0 | mp4 / mkv / mov / mpg / ts / avi / flv 等 ffprobe 可解析容器 |
| FR-02 | 输入探测并展示媒体信息 | P0 | 时长、分辨率、帧率、视频编码、体积、音轨数与每条音轨语言 / 标题 |
| FR-03 | 提取原唱音频为统一规格 PCM | P0 | 作为 UVR 输入与输出 `a:0` 的数据源 |
| FR-04 | 调用 UVR5.6 生成伴奏 | P0 | 模型可选、GPU / CPU 可选、输出文件名不硬编码 |
| FR-05 | **导入官方伴奏替代 UVR 分离** | P1 | 一等输入：选择伴奏文件后跳过 `SEPARATE`；来源写入报告 |
| FR-06 | 伴奏与源音频采样级对齐 | P0 | 重采样、声道统一、精确裁剪 / 补齐至源时长、消除起点偏移 |
| FR-07 | **视频一律转 H.265 / HEVC** | P0 | 原分辨率、帧率、时长不变；按压缩档压缩体积；编码器按硬件探测选择 |
| FR-08 | 封装为双音轨 MTV | P0 | 显式 `-map` 顺序；写入 title / language / disposition；默认 MP4 + `.mp4` |
| FR-09 | 输出自动校验并生成报告 | P0 | 音轨数量 / 顺序 / 编码 / 分辨率 / 时长 / 同步 / 画质 / 压缩率 |
| FR-10 | 提供歌曲链接获取歌词 | P1 | 仅网易云单曲链接或纯数字 ID（见 §6.3） |
| FR-11 | 歌词三分支降级 | P1 | 获取失败 / 为空 / 关闭烧录 → 均输出合法无字幕 MTV |
| FR-12 | 歌词预览、时间偏移、版本选择 | P1 | 原文 / 翻译 / 双语；LRC / SRT；±毫秒偏移 |
| FR-13 | 歌词烧录 | P1 | 默认关闭；并入**同一次 H.265 编码**；烧录不可逆需二次确认 |
| FR-14 | 中文字幕字体与样式配置 | P1 | 字体、字号、描边、位置、双行双语；打包字体资源 |
| FR-15 | 任务队列、进度、取消、重试、断点续跑 | P0 | 阶段化进度；取消能终止整个子进程树 |
| FR-16 | 硬件加速探测与自动回退 | P0 | 降级信息写入日志并在「详情」可查；主页面不弹横幅（§7.8） |
| FR-17 | 结构化日志与错误码、日志导出 | P0 | 日志脱敏，不含令牌与隐私 |
| FR-18 | **非单轨输入阻断确认** | P0 | 音轨数 ≠ 1 时进入 `NEEDS_CONFIRMATION`，不自动继续（见 §5.1） |
| FR-19 | 输出容器 / 扩展名可配置 | P1 | MP4 / MKV；`.mp4` / `.mkv`；默认 MP4 + `.mp4` |
| FR-20 | **应用内预览播放器** | P1 | 可预览输入视频与输出视频；播放 / 暂停 / 拖动 / 音量 |
| FR-21 | **预览音轨选择** | P1 | 输出预览可切换 `a:0` 原唱 / `a:1` 伴奏，切换不中断、进度不跳 |
| FR-22 | 预览代理服务 | P1 | 本地 HTTP + FFmpeg 转 H.264/AAC HLS 多音轨；生命周期与缓存受控（§7.7） |
| FR-23 | 逐字扫色（卡拉 OK 高亮） | P2 | 依赖逐字时间戳，见 §6.5 |
| FR-24 | 伴奏 30s 试听 / 波形摘要 | P2 | 归入预览模块 |
| FR-25 | **极简主页面与提示分级** | P0 | 主页面只保留导入 / 转换 / 预览 / 结果 + 首页歌词折叠区；其余信息按 L0–L3 分级（§7.8）；提供「详细模式」开关作为可回滚手段 |
| FR-26 | **首页歌词区** | P0 | 常驻可见、默认折叠；展开即 §7.9 完整配置，收起即保存；收起时零技术术语 |

### 2.2 非功能需求

| 编号 | 类别 | 指标 / 约束 |
| --- | --- | --- |
| NFR-01 | 保真 | 一律 H.265 重编码；分辨率 / 帧率 / 时长 / 色彩空间 / 旋转显示不变；PSNR ≥ 38 dB 或 VMAF ≥ 93（默认压缩档，实测后定稿） |
| NFR-02 | 同步 | 输出时长与源时长差 ≤ 1 帧（30fps 下 ≤ 40ms）；全程音画 drift ≤ 40ms |
| NFR-03 | 兼容 | 输出为 `codec_name=hevc` 的标准 MP4（hvc1 tag）；VLC / mpv / ffprobe 可列 2 条音轨；点歌系统按内容自动识别 |
| NFR-04 | 压缩 | 默认目标：输出体积 ≤ 源体积 60%；若源已是高压缩 HEVC，则要求「不显著增大」并 UI 提示（基准值由 P0 spike 实测写入） |
| NFR-05 | 性能 | 硬件编码路径耗时基准由 P0 spike 实测；**CPU 回退（libx265）必须给出预计耗时并允许后台排队**；8GB 内存机器不 OOM |
| NFR-06 | 预览 | 预览首帧出现 ≤ 2s（本地代理）；音轨切换不中断播放、进度偏移 ≤ 200ms |
| NFR-07 | 稳定性 | 单任务失败不影响队列其它任务；中间产物可复用；崩溃后可恢复 |
| NFR-08 | 安全 | 渲染进程 `contextIsolation: true`、禁用 nodeIntegration；外部进程 argv 数组传参；**预览服务只绑 `127.0.0.1` + 随机端口 + token 校验** |
| NFR-09 | 隐私 | 歌词请求只发送用户主动提供的歌曲 ID；不上传音视频文件；预览数据不出本机 |
| NFR-10 | 合规 | 个人自用；遵循 UVR 模型署名要求；歌词使用与站点「仅供个人学习交流」声明一致 |
| NFR-11 | 可观测 | JSON 结构化日志 + jobId；错误分类可统计；日志轮转与本地留存上限 |
| NFR-12 | 可维护 | UVR / 歌词 / FFmpeg / 预览代理全部经适配层，替换时不动业务层 |
| NFR-13 | 无障碍 | WCAG AA 对比度（正文 ≥ 4.5:1）、键盘可达、状态不仅靠颜色表达（见 §7.5） |
| NFR-14 | 体积 | 基础安装包不含 CUDA 运行时；加速包与模型权重**允许联网按需下载**并做 SHA256 校验 |
| **NFR-15** | **界面复杂度** | 首屏可见交互控件 ≤ **7**（含首页歌词折叠区）；歌词区**收起时**主页面零技术术语（不出现 HEVC / CRF / NVENC / HLS / ffprobe / `a:0` / `a:1` 等，音轨显示为「原唱 / 伴奏」）；零持久横幅、零告警卡片、零阶段条；所有技术信息可在「详情」两步内到达 |

## 3. 关键架构决策（含预期结果 / 风险 / 可回滚性）

| # | 决策 | 理由 | 预期结果 | 风险 | 可回滚性 |
| --- | --- | --- | --- | --- | --- |
| D1 | Electron 主进程编排，渲染进程纯 UI；媒体操作在主进程 / worker | 长任务不阻塞 UI | 界面始终响应、可取消 | IPC 契约需版本化 | 高 |
| D2 | 管线按「阶段 + 中间产物 + `.done` 标记」组织 | 可断点续跑、单阶段重跑、可审计 | 失败恢复成本低 | 磁盘占用，需缓存策略 | 高 |
| **D3** | **输出一律 H.265 重编码；字幕滤镜并入同一次编码** | 原分辨率 H.265 + 压缩体积；无「视频直通」选项 | 一次编码，画质损失最小、无二次编码 | CPU 模式编码慢；源已是 HEVC 时二次编码可能无收益 | 中：仅提供「源已是 HEVC」时的确认式跳过开关 |
| **D4** | **默认 MP4 容器 + `hvc1` tag + `.mp4` 扩展名，容器与扩展名均可配置** | 点歌系统自动识别，HEVC 在 MP4 中最通用 | 无需厂商 SDK / 私有格式 | 少数按扩展名索引的系统可能需改扩展名 → 一键可切 | 高 |
| D5 | 原唱轨也由统一 PCM 重新编码 | 保证两轨采样率 / 声道 / 编码 / 起点一致 | 切换无爆音、无静音间隙 | 原唱有一次有损转码 | 中：可配置「原唱直通」但需接受参数不一致风险 |
| D6 | UVR / 歌词 / FFmpeg / 预览代理各自独立适配层 | 四者均为易变外部依赖 | 替换供应商只改适配器 | 少量额外抽象工作 | 高 |
| D7 | 伴奏生成与歌词获取并行，互不阻塞 | 歌词是可选能力 | 失败降级为无字幕，主流程照常 | 需控制资源占用 | 高 |
| D8 | 硬件加速「探测 → 自检 → 降级」，禁止静默降级 | 结果可解释 | 用户知道为何变慢 | 探测有耗时 | 高 |
| **D9** | **伴奏来源二选一：UVR 自动生成 / 用户导入官方伴奏** | 同时兜底 live 场景分离质量 | 导入时跳过最耗时阶段，质量由用户保证 | 导入文件格式 / 时长不匹配 | 高：来源切换只影响一个阶段 |
| **D10** | **音轨数 ≠ 1 一律阻断为 `NEEDS_CONFIRMATION`** | 多轨无法确定哪条是原唱 | 不误处理、不静默丢弃音轨 | 批量任务可能被单个文件阻塞 | 高：确认项可配为「跳过该文件」 |
| **D11** | **预览走本地 HLS 代理，不依赖 Chromium 直接解 HEVC** | Chromium 对 HEVC 支持受限且需硬解（§7.7 查证） | 跨平台一致、音轨可无缝切换 | 需额外转码与本地服务 | 高：可降级为系统播放器 |
| **D12** | **提示分级 + 渐进披露：主页面极简，复杂度后置** | 面向用户的页面越简单越好；但可观测性、错误留痕、必要确认不能丢 | 首屏 ≤ 7 控件（含首页歌词折叠区）、收起时无术语与横幅；所有信息仍可在「详情」查到 | 用户可能找不到高级项或降级原因 | **高**：`UiPresentationPolicy` 配置驱动，一键切「详细模式」即恢复完整信息密度 |
| **D13** | **歌词区上首页但默认折叠** | 歌词放在首页；同时需与主页面极简共存 | 首页一步可达歌词；收起时只占一行、首屏 7 控件 | 展开后首页变长；若默认全展开会破坏极简 | **高**：一个「默认展开」开关即可切换形态或回滚 |

**职责边界铁律**：控制器不写业务逻辑；服务层不依赖 HTTP / IPC 请求对象；适配器只负责外部调用与产物落盘；任何阶段在边界处校验输入，绝不信任上层参数。

### 4.2 处理管线（阶段、权重、可取消点）

| 阶段 | 代号 | 职责 | 权重 | 产出 | 取消点 |
| --- | --- | --- | --- | --- | --- |
| 1 | `PROBE` | ffprobe 探测；**音轨数 ≠ 1 → `NEEDS_CONFIRMATION` 阻断**；记录 VFR / start_time / 旋转 / HDR / 源编码与体积 | 3% | `probe.json` | ✔ |
| 2 | `EXTRACT` | 提取 `0:a:0` → 统一 PCM WAV（原唱基准） | 4% | `original.wav` | ✔ |
| 3 | `LYRICS`（并行可选） | ID 解析 → 请求 → 解析 → LRC/SRT → ASS | 3% | `lyrics.ass` / `lyrics.status.json` | ✔ |
| 4 | `ACCOMPANIMENT` | **二选一**：UVR5.6 分离 / 导入官方伴奏（导入时几乎零耗时，权重转移给编码阶段）；写来源标记 | 40% | `instrumental.raw.wav` | ✔ |
| 5 | `ALIGN` | 伴奏重采样 / 声道统一 / 裁剪补齐至源时长 / 峰值与削波检查 | 5% | `instrumental.wav` | ✔ |
| 6 | `ENCODE_MUX` | **单次 H.265 编码**（原分辨率、压缩档）+ 可选 `-vf subtitles` + 显式 `-map` 双音轨封装 + 元数据 | 40% | `output.<container>` | ✔ |
| 7 | `VALIDATE` | ffprobe 断言 + 画质 / 压缩率 / 时长 / 同步校验 + 报告 | 5% | `report.json` | ✖（原子收尾） |

> 权重按「耗时占比」分配并在 P0 实测后校准；导入伴奏时 `ACCOMPANIMENT` 权重下调、`ENCODE_MUX` 上调。歌词分支与 `ACCOMPANIMENT` 并行，必须在 `ENCODE_MUX` 前汇合；任何失败只写状态文件，不抛出阻断性错误。

### 5.1 输入契约

| 字段 | 约束 |

| 拒绝项 | 加密 / DRM 片源、无音频、0 时长、ffprobe 失败 |

### 5.2 输出契约（默认 profile）

| 项 | 规格 |
| --- | --- |
| 容器 / 扩展名 | 默认 **MP4（`-tag:v hvc1`）+ `.mp4`**；可配置 MKV / `.mp4` / `.mkv`。点歌系统按内容自动识别，**不做私有适配** |
| 视频流 | **H.265 / HEVC**，`codec_name=hevc`；**原分辨率**（宽高不变、不缩放）；帧率、时长、SAR/DAR、旋转显示、色彩空间与源一致；按压缩档编码 |
| 压缩目标 | 默认档输出体积 ≤ 源体积 60%（或达到配置的目标体积）；源已是高压缩 HEVC 时要求「不显著增大」；实测基准由 P0 spike 写入 NFR-04 |
| 音频流 `a:0` | 原唱，`title=原唱`，`language=zho`，`disposition=default` |
| 音频流 `a:1` | 伴奏，`title=伴奏`，`language=zho`，`disposition=0`；来源（UVR / 导入）写入报告与可选自定义元数据 |
| 音频编码 | 两轨同 codec / 采样率 / 声道 / 位深（默认 AAC-LC 48kHz 立体声 192–256 kbps；可选 FLAC 无损档） |
| 时长 | 与源一致，误差 ≤ 1 帧 |
| 字幕 | 烧录时字幕是画面像素，不额外写软字幕轨；不烧录时不写字幕轨 |
| 命名 | 默认 `<源文件名>.mp4`，可配模板；**绝不覆盖源文件**；输出前检测同名冲突 |
| 附带产物 | `report.json`（含压缩前后体积、编码后端、伴奏来源、预览可用性）；中间产物在 jobId 目录，可配保留 / 自动清理 |

### 5.3 FFmpeg 调用契约示意（外部工具参数，非代码实现）

**提取原唱基准**：`ffmpeg -i <src> -map 0:a:0 -vn -ac 2 -ar 48000 -c:a pcm_s16le <work>/original.wav`

**单次编码 + 双音轨封装（唯一主路径）**：
```
ffmpeg -y -i <src> -i <work>/original.wav -i <work>/instrumental.wav
  -map 0:v:0 -map 1:a:0 -map 2:a:0
  -c:v <hevc_nvenc | hevc_videotoolbox | libx265> -crf <档位> -preset <档位>
  -pix_fmt yuv420p -tag:v hvc1 -movflags +faststart
  [-vf subtitles=<ass>:fontsdir=<fonts>]        ← 仅烧录开启时加入，同一编码通道
  -fps_mode passthrough -map_metadata 0
  -c:a aac -b:a 192k -ar 48000 -ac 2
  -metadata:s:a:0 title=原唱 -metadata:s:a:0 language=zho
  -metadata:s:a:1 title=伴奏 -metadata:s:a:1 language=zho
  -disposition:a:0 default -disposition:a:1 0
  <out>.mp4
```
> `-map` 的书写顺序即音频流顺序，**先原唱后伴奏**，是「音轨 0 原唱 / 音轨 1 伴奏」的唯一权威保证。
> `-tag:v hvc1` 提升 MP4 中 HEVC 的播放器识别率；`-fps_mode passthrough` 避免重编码引入重复 / 丢帧导致音画偏移；`-map_metadata 0` 与旋转 / 色彩元数据需显式校验保留。
> **HDR 源**：需透传 `color_primaries / color_trc / colorspace / master-display` 等并保留 10bit；P0 可先限定 SDR，HDR 列为 P2 并给出「暂不支持」提示。

**压缩档位（默认值需 P0 实测校准）**：

| 档位 | CRF / 码率策略 | 预期 | 适用 | 风险 |
| --- | --- | --- | --- | --- |
| 质量优先 | CRF 22–24，较高码率上限 | 画质近无损、压缩有限 | 收藏级片源 | 体积压缩不明显 |
| **均衡（默认）** | CRF 26–28 | 体积约为源 40–60%，VMAF ≥ 93 | 绝大多数 MV | 高动态画面可能出现色带 |
| 体积优先 | CRF 30–32 + 码率上限 | 体积最小 | 大批量曲库 | 画质可见劣化，需 UI 明确提示 |

> **不承诺固定压缩百分比**：源片码率差异极大。实际策略为「CRF 恒定质量 + 可选目标体积上限 + 二次编码兜底」，并在报告中给出实测压缩比；若源已是低码率 HEVC，允许「不显著增大」并提示用户改用质量档或跳过重编码。

### 5.4 跨进程 / 模块接口边界

| 边界 | 形式 | 契约要点 |

| Renderer ↔ Main | 类型化 IPC（invoke + 事件推送） | 入参运行时校验；事件含 `jobId / stage / percent / message / timestamp`；错误为 `{ code, stage, retryable, userMessage, action }` |

## 6. 外部服务集成约束

### 6.1 伴奏生成 — 已查证事实与集成约束

依据官方 `Anjok07/ultimatevocalremovergui` v5.6 README（2026-11-12 查阅）与实际集成验证：

| 事实 | 对设计的约束 |
| --- | --- |
| UVR v5.6 本体是 Tkinter 图形程序，**不提供命令行入口**；可脚本化的等价入口是 `audio-separator`（使用 UVR 训练的 MDX-Net 模型）：`<sep> <input> -m <model.onnx> --output_dir <dir> --single_stem Instrumental --output_format WAV --model_file_dir <dir>` | 以 CLI 为唯一集成面，不调用 GUI、不 import 上游内部模块；随包提供启动垫片 `resources/uvr/launch_separator.py`，参数与 `audio-separator` 完全一致 |
| Apple Silicon 上 ONNX Runtime 的 CoreML EP 无法执行 MDX-Net 计算图（算子不支持，报 `error code: -1`） | 分离固定使用 `CPUExecutionProvider`；只影响加载与推理耗时，不影响产出 |
| 模型族：MDX-Net（去人声 / 取伴奏，含 `UVR_MDXNET_KARA_2` 卡拉 OK 模型）、Demucs v4、VR Architecture | 默认 MDX-Net Inst / Kara；**模型名不硬编码**，从随包清单读取并由用户可选 |
| Windows NVIDIA：最低 GTX 1060 6GB，推荐 ≥ 8GB；AMD / Intel 有 DirectML 版 | 加速包按平台分发；显存不足直接回退 CPU |
| MPS 仅对 torch 系模型（Demucs）有效；MDX-Net 走 ONNX，与 MPS 无关 | 后端选择按「模型族 + CPU 架构」区分，不能只看操作系统 |
| 依赖 FFmpeg 处理非 WAV；首次加载模型数十秒到数分钟 | 输入统一先转 PCM WAV；明确「模型加载中」状态 |
| 代码 MIT；README 要求第三方使用模型**署名 UVR 及开发者** | 随包 `THIRD_PARTY_NOTICES` + 关于页署名；模型权重联网按需下载并校验 SHA256 |

**不可假设项**（实现时以随包版本实测，写入适配层常量表）：输出文件命名规则 → 扫描目录 + 按时长/声道探测定位；输出采样率 / 位深 / padding → 一律由 `ALIGN` 重新探测；CLI 版本差异 → 启动时存在性与可导入自检，失败则提示「分离不可用，可导入官方伴奏」。

**分离质量约束**：live 视频常含掌声、混响、和声与观众合唱，模型可能残留人声。提供：① 30s 试听；② 模型可切换；③ 波形 / 频谱摘要与试听入口；④ **P1 导入官方伴奏直接替代本阶段**（也是最主要的质量兜底）。

### 6.2 伴奏导入契约

| 项 | 约束 |
| --- | --- |
| 接受格式 | 常见音频与含音频的视频容器；由 FFmpeg 解码为 PCM，不依赖扩展名 |
| 时长差异 | 允许与源不同：以源时长为基准裁剪 / 补零；差异 > 2s 时在 UI 提示「伴奏与视频时长差异较大，请确认是否同一版本」 |
| 相位 / 起点 | 与 `original.wav` 做互相关检测，若显著错位提供 ms 级手动微调（P2）；**禁止自动变速对齐** |
| 质量校验 | 削波 / 直流偏移 / 静音检测；与源音轨完全相同（导入了原唱）时告警 |
| 报告标记 | `accompaniment.source=imported\|uvr`，模型与耗时字段相应留空 |

### 6.3 输出保真、压缩与音画同步（核心约束）

| 风险 | 处理 |
| --- | --- |
| 一律重编码带来的画质损失 | 默认均衡档 + PSNR/VMAF 硬断言；烧录字幕并入**同一次编码**，杜绝二次编码 |
| 分辨率 / 帧率被改变 | 显式禁止缩放与帧率变换；`-fps_mode passthrough`；`VALIDATE` 断言宽高、r_frame_rate、avg_frame_rate |
| 旋转 / SAR / HDR 元数据丢失 | `-map_metadata 0` + 显式透传色彩与旋转信息；抽帧比对显示方向；HDR 列为 P2 |
| 压缩不达预期 / 反而变大 | 报告实测压缩比；源已是低码率 HEVC 时提示并允许用户确认跳过重编码 |
| 伴奏比源长 / 短 | `ALIGN` 采样级裁剪 / 补零；禁止 `atempo` 拉伸 |
| 起点偏移 | 记录源 `start_time` / edit list，输出 normalize 到 0 起点 |
| 音轨参数不一致 | 两轨统一编码规格（D5），切换不重新初始化解码器 |
| VFR / B 帧 | `PROBE` 打标，`ENCODE_MUX` 显式处理时间戳，`VALIDATE` 校验首帧与首音频 pts 偏差 |

### 6.4 H.265 编码约束

| 项 | 约束 |
| --- | --- |
| 编码器矩阵 | Windows/NVIDIA `hevc_nvenc`；macOS Apple Silicon `hevc_videotoolbox`；CPU 回退 `libx265`（详见 §10.2） |
| FFmpeg 构建 | 必须同时含 `libx265`、各平台 HEVC 硬编、H.264 系编码器（预览代理）、`libass` / fontconfig、HLS muxer；启动时做能力自检 |
| 参数 | CRF 按压缩档；硬件编码器用等价质量参数（如 `cq` / `-q:v`）映射，需在 P0 spike 做「软硬编码画质对齐」基准 |
| 标识 | MP4 写 `-tag:v hvc1`；`codec_name=hevc` 为 V-12 硬断言 |
| 耗时 | CPU `libx265` 在 1080p 长视频上极慢 → 必须给出预计耗时、允许后台排队、提供体积优先档；**不得因慢而默认跳过转码** |
| 许可 | HEVC 存在专利池；个人自用影响低，但随包分发的编码器构建需保留第三方许可说明（非法律意见） |
| 资源争抢 | 分离（GPU）与编码（GPU）可能争用同一设备 → 默认串行执行两阶段；预览代理转码与主管线错峰或降优先级 |

### 6.5 歌词服务 `https://lyric.photix.cc/` — 已查证事实

页面（2026-11-12 抓取）为 Nuxt 网页工具「网易云歌词下载工具」：粘贴**网易云单曲链接或数字 ID**，导出 **LRC / SRT** 的**原文 / 翻译 / 双语**三版；FAQ 说明纯音乐可能「暂无歌词」、现场版 / 加速版可能需整体偏移；**明确写有「不可以商用这些歌词…仅供个人学习交流」**（与个人自用一致）。

实测内部 server route（2026-11-12，只读 GET）：

| 请求 | 响应 | 结论 |
| --- | --- | --- |
| `GET /api/lyric?id=1903172569` | HTTP 200，JSON：`lrc.version` / `lrc.lyric`（原文 LRC）、`tlyric.lyric`（翻译）、`klyric.lyric`（逐字，本例为空）、`code=200` | 可用数据源，返回的是网易云风格歌词 JSON，不是 LRC/SRT 文件 |
| `GET /api/lyric?id=0` | HTTP 200，`uncollected=true`，`lrc.lyric="[00:00.00]暂无歌词"` | 空歌词以**哨兵文本**表达，需专门判定 |
| `GET /api/lyric?id=not-a-number` | HTTP **200** + `{"code":400,"msg":"wrong params"}` | 业务错误用 HTTP 200 承载，必须解析 body 的 `code` |
| `GET /api/lyric?id=` | HTTP 400 | 参数缺失 |
| `Content-Type` | 成功时 `text/html`，参数错误时 `application/json` | **不能依赖 Content-Type**，按 body 能否解析成 JSON 处理 |
| `/robots.txt` | `User-agent: * / Allow: /` | 不构成 API 授权，也不构成商用许可 |

**约束结论**：① 未公开文档、无 SLA 的内部接口，适配层需契约测试与变更检测，解析失败即降级；② 仅支持网易云单曲链接或纯数字 ID，其它链接给明确「不支持」提示；③ 个人自用与站点声明一致，在首次启用处展示用途提示，烧录不可逆需二次确认；④ 请求只发送用户主动提供的 ID，不上传媒体文件；⑤ 超时 5–8s、最多 2 次退避重试、不得阻塞伴奏生成；⑥ **允许联网**，离线时降级为本地 LRC/SRT 导入 / 手工粘贴。

### 6.6 歌词三种分支的确定性行为

| 分支 | 判定 | 主管线行为 | 输出 | UI 反馈 |
| --- | --- | --- | --- | --- |
| 获取失败 | 超时 / DNS / 5xx / 非 JSON / `code≠200` / 解析异常 / 非法 ID | 降级继续，写 `lyrics.status=UNAVAILABLE` | 合法双音轨 H.265 MTV，**无字幕** | **状态行一行**「未找到歌词，已生成无字幕版本」；原因码在「详情」，重试 / 导入入口在**首页歌词区**（展开后），无横幅 |
| 歌词为空 | 空 / `[00:00.00]暂无歌词` / `uncollected=true` / 仅元信息行 | 降级继续，写 `lyrics.status=EMPTY` | 同上 | 状态行一行「这首歌没有歌词」；无告警卡 |
| 关闭烧录 | 配置 off | 跳过字幕分支（可仅取回预览） | 同上；可选外挂 `.lrc` | 主页面无任何提示；开关状态在**首页歌词区** |
| 成功 + 开启 | 有效时间轴且 ≥1 句 | 生成 ASS → **并入 `ENCODE_MUX` 的同一次 H.265 编码** | 带烧录字幕的双音轨 MTV | 歌词预览 / 偏移 / 字体在**首页歌词区**；仅烧录确认可打断 |

> 三种「无字幕」结果在主功能上必须**完全等价**：不因歌词问题产生损坏文件、缺失音轨、时长变化或任务失败。

### 6.7 歌词数据处理约束

- 格式：LRC / SRT 统一先转 ASS（可控字体、描边、双行双语、位置）；时间轴裁剪至视频时长，过滤元信息行；双语同时间戳原文在上、翻译在下。
- 偏移：±毫秒级全局偏移与对齐预览；现场版常见整体偏移，允许按文件保存。
- 逐字高亮（P2）：ASS `{\k}` / `{\kf}` 需逐字时间戳，实测 `klyric` 常为空，**首版只承诺整句显示**。
- 字体：随包可商用中文字体或明确系统字体回退链；FFmpeg 需启用 `libass` / `fontconfig`；Windows 下字幕路径需处理盘符冒号与中文转义。

### 7.7 预览播放器设计

**技术约束（2026-11-12 查证）**：Chromium 官方 audio/video 文档将 H.265/HEVC 列为**专有编解码器，仅限于 Google Chrome 且需硬件支持**；Electron ≥ v20（Chromium ≥104）在 macOS / Windows 上可通过 `PlatformHEVCDecoderSupport` 启用 **HEVC 硬解**，软解需自行编译打补丁的 Chromium / Electron（社区 `electron-codec-patches` 等方案需逐版本重打，维护成本高）。此外 Chromium 原生 HLS 支持有限、`<video>` 的 `audioTracks` API 在 Chromium 中并不可靠。因此**直接把输出的 H.265 文件塞进 `<video>` 不是可靠方案**。

**方案分级**：

| 方案 | 做法 | 预期结果 | 风险 | 可回滚性 | 定位 |
| --- | --- | --- | --- | --- | --- |
| **A（推荐）本地 HLS 多音轨代理** | 主进程 spawn FFmpeg 把源 / 输出实时转为 H.264/AAC 的 HLS（master playlist 含两条 audio rendition），经 `127.0.0.1` 本地服务 + token 提供给渲染层，用 HLS 客户端切音轨 | 跨平台一致、切轨不中断、进度可寻址、绕开 HEVC 解码限制 | 需额外转码与切片、占用 CPU/GPU | 高：可整体关闭 | **P1 主方案** |
| **B 直解 + 兜底** | 先尝试 `PlatformHEVCDecoderSupport` 直接播放；失败则生成单音轨 H.264 代理（切轨时重开）或调用系统播放器 | 实现最简、无本地服务 | 硬解依赖系统 HEVC 解码器；切轨会中断 | 高 | **P0 降级** |
| **C 自编译打补丁 Electron** | 给 Chromium 打 HEVC 软解补丁 | 应用内原生播放 | 每个 Electron 版本重编译、体积与维护成本高 | 低 | **不采用**，仅登记备选 |

> 方案 A 有两条外部佐证：Chromium 媒体架构实践建议「主进程 spawn FFmpeg 把非标准格式转为 fMP4/WebM 再流式传给渲染层」以突破编解码器限制；已有 KTV 项目采用「基于 HLS 多音轨，不中断播放且进度可寻址」实现原唱 / 伴唱实时切换，并优先硬件编码、自动回退软件编码。

**详细约束**：
1. **预览对象**：输入视频（PROBE 后即可播）、输出视频（VALIDATE 后）、可选伴奏 30s 试听；输入只有 1 条音轨时音轨下拉只显示 `a:0` 并禁用切换。
2. **切轨语义**：切换 `a:0 ↔ a:1` 只换音频 rendition，**视频流不重载、播放进度不跳**（NFR-06：偏移 ≤ 200ms）；切换后播放器角标同步显示当前音轨名。
3. **代理参数**：分辨率默认不超过 720p 或原分辨率（可配）、低码率 H.264 + AAC、切片时长 2–4s；复用硬件 H.264 编码器（`h264_nvenc` / `h264_videotoolbox`），无硬件时 `libx264` veryfast；与主管线错峰，避免抢占 GPU / CPU。
4. **生命周期与安全**：仅绑 `127.0.0.1` + 随机端口 + 一次性 token；URL 不含绝对路径；切换预览对象、关闭页面、任务完成 / 取消时停止子进程并清理切片；空闲 TTL 自动回收；**显式使用 `127.0.0.1` 而非 `localhost`**，避免本机 `::1` 解析导致「连上即被 RST」（本机已验证踩坑）。
5. **降级链**：代理转码失败 → 方案 B 直解 → 系统播放器打开原文件；主页面仅在状态行留一行文案（如「预览已改用系统播放器」），「重试代理」入口放「详情」；任何降级都在日志写原因码，不静默、不弹窗。
6. **验收**：见 V-16、A-06；需覆盖「输入 H.264 / 输出 H.265」「有 / 无硬件加速」「切换音轨 10 次」三组用例。

| --- | --- | --- | --- | --- |
| **L0 主页面** | 文件、时长、预览、音轨（原唱 / 伴奏）、**歌词折叠区标题行**、开始转换、完成结果 | 常驻，最多 7 个控件 | 否 | 「MV.mp4 · 03:30」「歌词（可选）▸」「完成 · 198 MB」 |
| **L1 状态行** | 一句话进度 + 进度条 + 取消；一行结果文案 | 单行、灰色、无颜色轰炸 | 否 | 「正在生成伴奏…」「未找到歌词，已生成无字幕版本」「使用 CPU 模式 ⓘ」 |
| **L2 详情抽屉** | 阶段与权重、编码后端、CRF / 压缩比、伴奏来源、歌词状态、降级原因码、错误码、结构化日志、校验报告 | 点击 [详情] 才展开 | 否 | `E_GPU_FALLBACK`、`backend=cpu`、`report.json` |
| **L3 必要打断** | 需用户决策或不可逆 | 模态，一行文案 + 最少按钮 | **是** | 非单轨确认、烧录二次确认、任务失败且需选择动作 |

**策略效果与风险（分级）**：

| 项 | 预期结果 | 风险 | 可回滚性 |
| --- | --- | --- | --- |
| 默认极简 | 新用户无需理解任何技术概念即可完成转换；首屏 ≤ 7 控件（含歌词折叠区） | 高级项 / 降级原因不易被发现 | 高：「详细模式」一键恢复 |
| 信息后置而非删除 | 排障、验收、审计所需数据全部保留在详情与日志 | 抽屉实现需保证所有 L2 事件都有留痕 | 高：策略表集中，缺项可用测试检出 |
| 不静默降级 | 降级仍可查、可解释，但不再占据主页面视觉 | 用户可能没注意到速度变化 | 高：状态行 ⓘ + 详情 + 日志三重可查 |

**首页歌词区与配置视图的归属**：歌词区是**首页 L0 的按需展开层**——标题行常驻（计入 7 控件），展开后的表单不属于事件提示，不受首屏约束，但仍渐进披露（字幕样式再折叠一层）。「更多设置」「设置」仍是用户主动进入的视图。这些视图内部的状态与失败文案一律按 L1 的「一行平实语言」书写，原因码进 L2 详情。仅「烧录不可逆确认」属于 L3。

**状态机**：`OFF`（默认）→ `FETCHING` → `READY` / `UNAVAILABLE` / `EMPTY`；`READY` 且勾选烧录 → `BURN_CONFIRMED`。任何状态都可收起；收起 / 展开只切换视图，配置写入 `JobConfig.lyrics`，不触发转换。

**四种状态在首页歌词区 / 主页面状态行 / 输出的表现**（对应原始需求的三分支，是本节的核心验收对象）：

| 状态 | 首页歌词区内 | 主页面状态行 | 输出文件 | 可恢复动作 |
| --- | --- | --- | --- | --- |
| **获取失败** `UNAVAILABLE` | 一行「没拿到歌词，可重试或导入本地文件」+ [重试] [导入] [粘贴]；无横幅 | 「未找到歌词，已生成无字幕版本」 | 合法无字幕 H.265 双音轨 MTV | 重试 / 本地导入 / 直接完成 |
| **歌词为空** `EMPTY` | 一行「这首歌没有歌词」；**烧录开关禁用** | 「这首歌没有歌词」 | 同上 | 本地导入 / 直接完成 |
| **关闭烧录** `OFF` / `READY` 不烧 | 歌词仍可预览，可选导出外挂 `.lrc`；烧录开关 off | 无提示 | 同上；无字幕轨 | 随时回来打开 |
| **成功 + 开启** `BURN_CONFIRMED` | 显示句数、时间轴预览、样式；勾选时一次不可逆确认 | 无提示 | 带烧录字幕的双音轨 MTV | — |

> 三种「无字幕」输出在主功能上**完全等价**：不因歌词问题产生损坏文件、缺失音轨、时长变化或任务失败（见 §6.6、V-10）。

**约束与接口边界**：
- **输入**：仅网易云单曲链接或纯数字 ID；其它平台链接给明确「不支持」提示，不笼统报错。ID 从 `music.163.com/#/song?id=<数字>` 或纯数字提取。
- **来源兜底**：在线获取 / 本地 LRC·SRT 导入 / 手动粘贴三选一；在线失败不阻塞另外两条。
- **合规**：个人自用，与站点「仅供个人学习交流」一致；用途提示放在展开区底部（收起时首页不显示）；烧录为不可逆操作，勾选时触发 L3 白名单中的那一次确认，文案一行说清后果。
- **时间轴**：偏移 ±ms 可保存为该文件的配置；点击歌词行通过 IPC 让**预览播放器**跳到对应时刻做对齐预览；逐字扫色需逐字时间戳，首版只承诺整句显示（P2）。
- **配置与执行分离**：此页只写 `JobConfig.lyrics`；`LyricsProvider` / `SubtitleConverter` / ASS 生成在管线 `LYRICS` 阶段执行，字幕滤镜并入 `ENCODE_MUX` 的同一次 H.265 编码（§4.2、§6.6）。
- **形态开关**：默认折叠；「默认展开」开关可切换为首页常驻全展开，此时首屏控件 > 10，需放宽 NFR-15 并重跑 V-17/V-18。

## 8. 异常处理与进度反馈

### 8.1 错误体系

类型化错误对象（Renderer 只见规范化结构，绝不含堆栈 / 内部细节）：`code` / `stage` / `retryable` / `userMessage`（含下一步动作）/ `action` / `cause`（仅本地日志）。

**错误码分组**：输入类 `E_INPUT_*` / `E_INPUT_MULTI_TRACK_CONFIRM`；探测类 `E_PROBE_*`；伴奏类 `E_UVR_*` / `E_ACCOMPANIMENT_IMPORT_INVALID`；歌词类 `E_LYRICS_*`；字幕类 `E_SUBTITLE_*`；编码类 `E_ENCODE_HEVC_FAILED` / `E_HEVC_ENCODER_UNAVAILABLE` / `E_COMPRESSION_TARGET_MISSED`；封装类 `E_FFMPEG_MUX` / `E_DISK_FULL`；预览类 `E_PREVIEW_PROXY` / `E_PREVIEW_TRACK_SWITCH`；硬件类 `E_GPU_FALLBACK`（事件非错误）；校验类 `E_VALIDATION_*`；控制类 `E_CANCELLED`。

### 8.2 异常矩阵与恢复动作

| 场景 | 检测 | 自动处理 | 用户可选动作 |
| --- | --- | --- | --- |
| 源文件损坏 / 无音频 | ffprobe 失败 | 拒绝任务 | 换文件 |
| **音轨数 ≠ 1** | PROBE | **阻断为 `NEEDS_CONFIRMATION`**，展示音轨清单；不自动继续 | 指定原唱轨继续 / 跳过文件 |
| **导入伴奏无效**（无音频 / 损坏 / 与源音轨相同） | 探测 + 互相关 | 拒绝导入并保留 UVR 路径，不阻断任务 | 换文件 / 改用 UVR 生成 |
| 伴奏与源时长差 > 2s | ALIGN | 提示「可能不是同一版本」，等待确认 | 继续 / 换文件 |
| UVR 模型缺失 / 校验失败 | 自检 | **联网下载模型**（SHA256 + 断点续传） | 手动指定模型目录 / 改用导入伴奏 |
| UVR OOM / 无产物 | 非零退出 / 扫描 | 降级 CPU 一次；仍失败则任务暂停并建议导入伴奏 | 换轻量模型 / 导入官方伴奏 |
| HEVC 编码器初始化失败 | 自检 | 回退 `libx265` 一次，写降级事件与耗时预估 | 强制指定后端 / 改压缩档 |
| 压缩未达目标 | VALIDATE | 报告标「未达压缩目标」，不标失败 | 换体积优先档重跑编码阶段 |
| 歌词失败 / 为空 / 关闭 | §6.6 | 三路降级为无字幕 | 重试 / 本地导入 / 粘贴 |
| 字幕字体 / libass 不可用 | 预检 | 关闭烧录并提示（不阻断主流程） | 安装字体 / 关闭烧录 |
| **预览代理失败** | HTTP / 转码错误 | 降级方案 B 直解 → 系统播放器 | 重试代理 / 打开系统播放器 |
| 磁盘不足 / 用户取消 / 校验不通过 | 预检 / UI / VALIDATE | 清理中间产物 / 终止进程树 / 标记「需复核」 | 换目录 / 断点续跑 / 重跑编码 |

### 8.3 进度反馈

- **主页面（L1）**：状态行一句人话（「正在生成伴奏…」「正在压缩视频…」）+ 进度条 + [取消]；不显示阶段条、百分比、预计剩余、阶段名、编码后端。
- **详情抽屉（L2）**：阶段加权（§4.2）、已耗时 / 预计剩余、编码后端、降级原因、压缩档与日志；**H.265 在 CPU 模式下的耗时预估放这里**（libx265 极慢），不确定阶段用 indeterminate 并说明原因。
- 事件仍含 `jobId / stage / percent / message / timestamp`，由 `UiPresentationPolicy` 决定呈现级别；stdout 进度解析失败时不伪造百分比。
- 取消终止**整个子进程树**（POSIX 进程组 / Windows `taskkill /T`），同时停止预览代理；取消后状态为「已取消」，与「失败」区分。
- **幂等与断点续跑**：`jobId = hash(文件指纹 + 配置指纹)`（含压缩档与伴奏来源），配置变更即新 jobId；每阶段 `.done` 标记；压缩档改动只重跑 `ENCODE_MUX`。
- **日志**：JSON 结构化、含 jobId / 阶段 / 后端 / 原因码；脱敏；轮转；一键导出诊断包。

## 9. 输出校验与验收标准

### 9.1 自动校验（`VALIDATE` 阶段，全部硬断言）

| 编号 | 校验项 | 判据 | 方法 |
| --- | --- | --- | --- |
| V-01 | 音轨数量 | `ffprobe -select_streams a` 恰好 2 条 | ffprobe JSON |
| V-02 | **音轨顺序** | `a:0` title=原唱且波形与源互相关 ≥ 0.99；`a:1` title=伴奏且与源音轨不同（UVR 产物人声频段能量显著下降 / 导入产物仅校验不同） | 元数据 + PCM 比对 |
| V-03 | 默认播放轨 | `a:0` 带 `disposition.default`，`a:1` 不带 | ffprobe |
| V-04 | 编码一致性 | 两轨 codec / sample_rate / channels 一致 | ffprobe |
| **V-05** | **H.265 与原分辨率** | `codec_name=hevc`；宽高、SAR/DAR、旋转显示、帧率、时长与源一致 | ffprobe + 抽帧 |
| **V-06** | **画质** | PSNR ≥ 38 dB 或 VMAF ≥ 93（默认档）；烧录时差异限于字幕区 | 抽样比对 |
| V-07 | 时长 | `abs(out.duration - src.duration) ≤ 1 帧`（≤ 40ms @30fps） | ffprobe |
| V-08 | **音画同步** | 首视频帧 pts 与首音频 pts 偏差 ≤ 40ms；全程 drift ≤ 40ms | 时间戳扫描 |
| V-09 | 字幕时间轴（烧录时） | 末句结束 ≤ 视频时长；句数 ≥ 1；中文不缺字 | ASS 解析 + 抽帧 |
| V-10 | 三分支一致性 | 失败 / 空 / 关闭下 V-01~V-08 全通过且无字幕轨 | 用例矩阵 |
| V-11 | 文件可播放 | ≥2 个播放器可打开并列出 2 条音轨 | 冒烟测试 |
| **V-12** | **编码标识** | `codec_name=hevc`；MP4 profile 写 `hvc1` | ffprobe |
| **V-13** | **压缩率** | 默认档输出体积 ≤ 源 60%（或达到配置目标）；源已是低码率 HEVC 时「不显著增大」 | 体积比对 + 报告 |
| **V-14** | **伴奏来源标记** | `report.accompaniment.source` 与实际路径一致（uvr / imported） | manifest 断言 |
| **V-15** | **多轨阻断** | 非单轨输入不会自动产出文件，状态为 `NEEDS_CONFIRMATION` 或 `SKIPPED` | 状态机用例 |
| **V-16** | **预览音轨切换** | 输出预览可列 `a:0` / `a:1`；切换 10 次不中断、进度偏移 ≤ 200ms | 自动化 + 人工 |

> 任一硬断言失败：文件保留但**不得标记为成功**，报告标注失败项与建议动作；V-13 未达标可标「提示」而非失败（可配置）。

### 9.2 人工验收

| 编号 | 验收动作 | 通过标准 |
| --- | --- | --- |
| A-01 | **原唱 / 伴奏切换**：播放至中段切换 `a:0 → a:1 → a:0` | 进度不跳、无中断、无爆音 / 静音间隙 |

| macOS | `.dmg`（签名 + 公证） | arm64 / x64 分别构建 | Developer ID + notarization + hardened runtime；内嵌 Python / PyTorch 的 JIT / 未签名可执行内存 entitlements **须 P0 实测**；Gatekeeper quarantine 对 sidecar 的影响需实测 |

**技术栈**：Electron 主进程 Node + React/Vue 渲染层 + electron-builder；`contextIsolation: true`、`nodeIntegration: false`、显式 CSP；预览客户端（HLS.js 一类）作为前端依赖，**引入前先核对项目清单与许可**；配置集中、启动校验、快速失败；本工具无需任何密钥，`.env.example` 仅占位。

**Sidecar 清单**：
- FFmpeg / FFprobe 静态构建：**必须含 `libx265`、`hevc_nvenc`、`hevc_videotoolbox`、`libx264`、`h264_nvenc`、`h264_videotoolbox`、`libass`、`fontconfig`、HLS muxer**；
- UVR5.6 Python 运行时（版本锁定 + manifest）；
- 模型权重：**允许联网按需下载**，SHA256 校验、断点续传、失败重试、来源可配；随包附 UVR 署名与第三方许可；
- 中文字体与 ASS 模板；
- 加速包（CUDA torch / DirectML / MPS 依赖）与基础包分离分发；允许联网下载。

### 10.2 硬件加速决策矩阵

| 平台 / 设备 | 分离后端（MDX-Net） | **主编码（H.265）** | 预览代理（H.264） | 触发条件 |
| --- | --- | --- | --- | --- |
| Windows + NVIDIA（≥6GB，建议 ≥8GB） | ONNX CUDA EP（可用时）/ CPU EP | **`hevc_nvenc`** | `h264_nvenc` | nvidia-smi + 显存达标 + HEVC 编码自检 |
| Windows + AMD / Intel | DirectML（可用时）/ CPU EP | `libx265`（若平台 HEVC 硬编可用则启用） | `libx264` / 平台编码 | 探测通过后启用；失败即回退 |
| macOS Apple Silicon（M1+） | **CPU EP**（MDX 走 ONNX，CoreML EP 不支持该计算图） | **`hevc_videotoolbox`** | `h264_videotoolbox` | HEVC 编码自检通过 |
| macOS Intel | CPU EP | `libx265` | `h264_videotoolbox`（若可用）/ `libx264` | — |
| 无 GPU / 驱动不符 / 显存不足 / OOM / 编码器失败 | **CPU EP** | **`libx265`** | **`libx264` veryfast** | 任一探测或运行期失败 |

> 分离后端只决定加载与推理耗时；编码后端独立决策。软硬编码画质对齐：硬件编码器的 `cq` / `-q:v` 与 `libx265 -crf` 不等价，需建立映射基准表，保证 V-06 在各后端一致通过。

### 10.3 无硬件加速时的回退策略（明确、可观测）

1. **探测顺序**：平台 → 架构 → 设备 → 驱动 → 显存 → 模型兼容 → **HEVC 编码器 1 秒自检** → 1 秒推理自检。任一环失败记录具体原因码。
2. **自动降级一次，不静默但也不扰民**：主页面状态行仅显示「使用 CPU 模式 ⓘ」；原因码、`backend=cpu, reason=...` 与 H.265 软件编码耗时预估全部进入「详情 / 日志」。「不静默」= 信息可达 + 日志留痕 + 一键展开（§7.8）。
3. **CPU 模式参数保守化**：单任务、调小 UVR segment / chunks、`libx265` 使用较快 preset + 体积优先档可选、长视频分块、内存上限监控；**不因慢而跳过 H.265 转码**（FR-07 为硬需求），改为允许后台排队与耗时预估。
4. **用户可控**：设置页可强制 CPU / 指定后端；可调压缩档以权衡耗时与体积；预览代理在 CPU 模式下自动降为更低分辨率 / 码率，避免与主管线抢资源。
5. **运行期二次降级**：分离或编码 OOM / 编码器失败时终止子进程、清理半成品、以 CPU 重跑该阶段一次；两次失败才判任务失败。
6. **可回滚**：降级只改变后端参数，不改变管线与产物契约；恢复 GPU 后同一 jobId 从对应阶段重跑。

### 10.4 其它平台注意点

- **点歌系统**：自动识别，**不做任何容器 / 编码兼容适配**。容器与扩展名保留可配置项仅为方便用户管理。
- **路径**：中文 / 空格 / 反斜杠 / 冒号一律参数数组传递；FFmpeg `subtitles` 滤镜路径按平台转义。
- **本地预览服务 IPv6 坑**：宿主可能同时监听 `[::]:port`，若应用只监听 IPv4，访问 `localhost`（解析为 `::1`）会「连上即被 RST」（表现为 `ERR_CONNECTION_RESET` / `Recv failure: Connection reset by peer`）。**服务与 UI 统一用 `127.0.0.1`**；或只绑定 IPv4 让浏览器自动回退。
- **首次运行**：UVR 模型加载可能数分钟，明确「模型加载中」；联网下载有进度 / 取消 / 校验。
- **资源**：8GB 统一内存机器（如 Mac mini M2 8GB）默认单任务、保守参数；提供缓存目录与容量上限。
- **HEVC 许可**：编解码器随包分发需保留第三方许可说明；个人自用场景下影响低（非法律意见）。
- **签名**：内嵌 Python 与动态库在 hardened runtime 下的 entitlements、Windows SmartScreen 与代码签名证书，列为 P0 spike 验证项。
