主目标不依赖歌词：即使歌词完全不可用，也必须产出音画同步、HEVC 编码、音轨顺序正确的合法 MTV 文件。

05歌词三种分支：结果必须等价

允许联网取词；歌词服务为站点内部 server route（无公开文档、无 SLA），页面声明「仅供个人学习交流」与「个人自用」一致。所有失败都降级为合法无字幕 H.265 双音轨文件。

① 获取失败 UNAVAILABLE

超时 / 5xx / 业务码 400 / 非 JSON / 契约变更 / 非网易云链接。

  • 超时 5–8s，最多 2 次退避重试
  • 业务错误以 HTTP 200 + code=400 承载，必须解析 body
  • Content-Type 在 text/html 与 application/json 间不一致
  • UI：状态行一行「未找到歌词，已生成无字幕版本」；重试 / 导入在首页歌词区（展开后），无横幅

② 歌词为空 EMPTY

纯音乐、未收录、仅有「作词 / 作曲」元信息行。

  • 哨兵 [00:00.00]暂无歌词 与 uncollected=true
  • klyric 逐字歌词实测常为空，不可依赖
  • UI：状态行一行「这首歌没有歌词」；无告警卡
  • 输出仍为合法双音轨 MTV

③ 关闭烧录 OFF

用户主动关闭，或取回歌词仅用于预览。

  • 跳过字幕分支（可仅预览不写字幕）
  • 可选附带外挂 .lrc 侧车文件
  • 不额外生成软字幕轨，避免双份歌词
  • 输出仍为合法双音轨 MTV
成功 + 开启时：字幕并入 ENCODE_MUX 的同一次 H.265 编码。烧录为不可逆操作，需二次确认；个人自用与站点声明一致，商业分发不在本期范围。UVR 模型按官方 README 要求保留署名。

06硬件加速矩阵与无加速回退

分离后端只决定加载与推理耗时，编码后端独立决策：Windows NVIDIA 最低 GTX 1060 6GB（建议 ≥8GB）；Apple Silicon 上 MDX-Net 走 ONNX，因 CoreML EP 不支持该计算图而固定用 CPU EP。H.265 主编码与预览代理各有一条后端链。

08预览播放器：为什么需要代理

Chromium 官方把 H.265/HEVC 列为专有编解码器，「限于 Chrome 且需硬件支持」；Electron ≥ v20 可通过 PlatformHEVCDecoderSupport 启用 HEVC 硬解，软解需自编译打补丁的 Chromium/Electron。因此把输出 H.265 文件直接塞进 <video> 不可靠。

方案 A · 本地 HLS 多音轨代理 推荐 P1

FFmpeg 实时转 H.264/AAC HLS，master playlist 含两条 audio rendition；本地服务经 127.0.0.1 + token 提供，客户端切音轨。

  • 跨平台一致、切轨不中断、可寻址
  • 绕开 HEVC 解码限制
  • 依据：Chromium 媒体架构实践 + 已有 KTV 项目 HLS 多音轨切轨
  • 风险：额外转码开销，需与主管线错峰

方案 B · 直解 + 兜底 P0 降级

先尝试 HEVC 硬解直接播放；失败则生成单音轨 H.264 代理（切轨重开）或调用系统播放器。

  • 实现最简、可无本地服务
  • 硬解依赖系统 HEVC 解码器
  • 切轨会中断、进度可能跳
  • 适合 P0 验证与 A 失败时兜底

方案 C · 自编译打补丁 Electron 不采用

给 Chromium 打 HEVC 软解补丁，实现应用内原生播放。

  • 每个 Electron 版本需重编译
  • 构建与维护成本高、体积大
  • 仅登记为长期备选
安全与生命周期：只绑 127.0.0.1 + 随机端口 + 一次性 token；URL 不含绝对路径；切换预览对象、关闭页面、任务完成 / 取消时停止子进程并清理切片；空闲 TTL 自动回收。必须用 127.0.0.1 而非 localhost——本机实测 localhost 解析到 ::1 时会出现「连上即被 RST」。
验收：V-16 切轨 10 次不中断、进度偏移 ≤ 200ms；A-06 输入 / 输出均可播且无残留转码进程。

09输出校验与验收标准

自动硬断言 V-01~V-20 + 人工验收 A-01~A-08；任一硬断言失败，文件保留但不得标记为成功（V-13 压缩未达标可配置为「提示」而非失败）。

实施纪律：一次只变更一个变量，每步变更后立即重跑 V-01~V-20 与 A-01~A-08；实测与文档冲突时先更新文档再改实现。

P0 · SPIKE

技术验证
